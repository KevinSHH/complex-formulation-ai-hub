WHY为什么制剂研发人员需要这套框架？

传统路径

处方筛选靠经验和正交试验，一个 LAI 从立项到确定处方往往要做几十上百组体外释放实验，周期以年计。

框架做了什么

把文献里已有的处方-释放数据"喂"给 ML 模型，让计算机先在虚拟空间筛选候选处方，再用 PBPK/PD 预测体内表现，只把最有希望的少数几个送进实验室。

你不需要懂 ML

把 ML 模型当成一个"阅方无数的老师傅"：你告诉它处方组成，它凭经验（数据）估出释放曲线。SHAP 只是告诉你老师傅最看重哪些因素。本页每个模块都配了"说人话"的解释。

阅读路线建议：按导航栏 ①→⑤ 顺序阅读即可走完整个闭环；每个页面的开头都有一段"这一页在讲什么"，结尾有"关键结论"。如果你想把这套框架用在自己的产品上，直接跳到「移植指南」，那里有 step-by-step 的操作清单。

环节 ② · 机器学习预测

让模型学会"看处方、估释放"

给定一个处方的组成（API 性质、PLGA 规格、溶剂），模型预测它在各时间点的累计释放度。评测方式刻意做得很严格——按"处方"分组做交叉验证，确保模型见到的是完全没见过的新处方，而不是背下了答案。

给 ML 小白的三个概念：
  • R²（决定系数）：预测有多准。1.0 = 完美，0 = 和瞎猜一样。0.9 以上在药学数据里属于优秀。
  • 嵌套 GroupKFold 交叉验证：把 155 个处方分成 5 组，轮流拿 4 组训练、1 组考试，且同一处方的所有时间点必须同组——防止模型"作弊"。
  • 场景 A / B：场景 A 允许模型看到"前 24 小时释放量"（release_day1），场景 B 不允许。场景 B 更接近真实处境——新处方还没做实验，你不知道它第一天释放多少。

SHAP：模型最看重哪些因素？

SHAP 值回答"每个变量对预测结果的贡献有多大"。排除掉时间本身（release_time_h）这个机械性因素后，前 24h 突释量、API 脂溶性 logP、API 浓度是处方设计的三大杠杆——这与药剂学直觉完全吻合。

关键结论：① 树模型 R²≈0.91，足以支撑后续虚拟筛选；② 去掉 day1 特征后 R² 降至 0.855，说明"首 24 小时释放行为"携带了最多的处方信息——做新处方时，第一天释放数据最值得优先测；③ SHAP 排序（release_time > release_day1 > api_logp > api_conc_pct）与论文完全一致。
环节 ③ · PBPK/PD 生理建模

从"体外释放"到"体内药效"的翻译器

体外释放曲线再漂亮，也不能直接告诉我们药效能维持多久。PBPK/PD 模型充当翻译器：PBPK（生理药代）模拟药物注射进关节腔后如何分布和清除，PD（药效）再把浓度换算成镇痛效果（ADP 评分）。

① 释放函数（体外）

三相释放模型：突释相 + 扩散相 + 溶蚀相。以 Zilretta®（曲安奈德缓释微球）为标杆拟合：24h 突释 39.7%，零级速率 0.147 %/h。

② IA 三室 PBPK（体内）

关节腔分为滑液 → 滑膜 → 滑膜下三个房室，药物逐层渗透并被系统循环清除。内膜下室 Cmax = 1.089 µg/mL，半衰期 33.6 天。

③ Sigmoid Imax PD（药效）

浓度越高、镇痛评分 ADP 越低；ADP < 3 视为有效镇痛。炎症本身会让 ADP 随时间回弹（kt 项），药效终点由浓度曲线与回弹速度的赛跑决定。

模拟结果：缓释 vs 速释

Zilretta®（缓释）ADP 在 3 以下维持了 14.69 周；普通 TCA 注射（速释）只维持 8.49 周。缓释把镇痛时长延长了 73%——这就是 LAI 的临床价值。

环节 ④ · 闭环优化

让计算机替你试处方：从 F1 失败到 F4 成功

这是框架的"大脑"：贝叶斯优化在处方空间里自动搜索，每猜一个处方就用 ML 模型预测其释放曲线，再用 f₂ 相似因子打分——像不像目标产品（Zilretta®）？不像就换方向再猜，直到找到合格候选。

f₂ 相似因子（说人话版）

FDA 用 f₂ 判断两条释放曲线是否"相似"：f₂ ≥ 50 即相似。论文创新性地加了惩罚项——如果突释量、曲线形状、释放速率超出目标窗口（Me-too/Me-better 标准），就打折，让"曲线相似但关键属性不对"的处方无处遁形。

两轮迭代的智慧

第一轮在宽松空间里搜（L/G 比 50-100、分子量 10-150 kDa），得到的 F1-F3 全部失败；分析失败原因后缩小搜索空间（L/G 75-85、MW 60-100、只用 NMP），第二轮一击即中——F4 成功。

四个候选处方的释放曲线

黑线为目标（Zilretta®）。F1 释放太快（突释 41%），F2 太慢（突释仅 1.8%），F3 形状对了但关键参数超窗，只有 F4 全部达标。

f₂ 评分：惩罚机制如何工作

F3 最能说明惩罚的价值：标准 f₂ 高达 63.4（曲线形状确实像），但突释和速率超窗，惩罚后掉到 45.7 —— 不合格。虚线为 f₂=50 合格线。

关键结论：闭环优化的精髓不在"优化算法"本身，而在失败-分析-收缩-再试的迭代策略：第一轮广泛探索摸清边界，第二轮收缩到物理合理的子空间精确打击。F1-F3 的失败不是浪费，而是为 F4 划定了成功的范围。
环节 ⑤ · 分子动力学验证

ML 告诉你"这个处方大概率行"，MD 模拟则从分子层面解释"为什么行"——API 分子和 PLGA 链之间靠得多近？形成几个氢键？API 在聚合物里跑得快不快？这些微观性质决定了释放的宏观行为。

MD 轨迹示意（4 指标随模拟时间的演化）

怎么读这些数字

  • 最小距离 < 0.2 nm：API 与 PLGA 紧密贴合，存在直接相互作用
  • 氢键数多：API 被"锚定"在聚合物网络中，突释倾向低
  • 扩散系数小：API 在凝胶中移动缓慢，释放更持久

在本框架中的角色

MD 是闭环的最后一道验证：优化给出的候选处方（如 F4），在做湿实验之前，先在原子尺度确认 API-辅料相互作用是否符合预期。若 MD 显示结合松散，可及早回头调整，避免浪费实验资源。

简化声明：本复现为示意性轨迹（基于论文报告值参数化），非 GROMACS 全原子模拟。所有指标均落在论文报告区间内，用于演示 MD 在闭环中的验证逻辑。
Reuse Playbook · 把框架移植到你自己的产品

Step by Step：用这套框架开发你的下一个 LAI

本框架的价值不止于复现一篇论文——它是一套可移植的方法论。以下 7 步把每个环节转化为可执行的操作清单，标注了每步的输入、输出、对应代码文件，以及换产品时哪些地方必须改。

1

明确产品目标与目标窗口

写下三件事：① 目标产品（如某个已上市 LAI，做 Me-too）或目标性能（Me-better：更长药效/更低突释）；② 治疗窗口（药效维持几周？ADP 或等效指标的阈值？）；③ 关键质量属性窗口——本论文用"突释 10-20%、形状 b 1.2-1.8、速率 0.04-0.07 %/h"，你的产品要按临床需求重新定义。

输入
临床/监管需求、目标产品说明书与文献
输出
目标窗口定义表（突释/形状/速率/药效时长）
换产品要改
f2_similarity.py 中的窗口边界与惩罚系数
2

构建你自己的处方数据集

系统检索你的剂型/给药途径相关文献，提取"处方组成 + 释放曲线"成对数据。坚持纳入标准（建议同样从三组分体系起步），变量命名对齐统一规范。数据量参考：155 个处方即可训练出 R²≈0.9 的模型——质量（变量完整、释放曲线可靠）比数量更重要。

输入
文献 PDF、公司内部历史处方数据
输出
ml_dataset.csv（处方 × 时间点长表）
换产品要改
preprocessing/build_dataset.py 的纳入标准；feature_engineering/api_descriptors.py 的 API 描述符
3

训练 ML 模型并验证可信度

直接套用嵌套 GroupKFold 流程训练 LightGBM/XGBoost/RF。两条验收线：① 场景 A（含 day1）R² ≥ 0.85；② SHAP 排序必须经得起药剂学常识检验——如果模型认为"溶液体积"比"PLGA 分子量"更重要，多半是数据有泄漏或噪声，回去查数据，不要硬用。

输入
步骤 2 的数据集
输出
训练好的模型 + cv_results + SHAP 排序
换产品要改
training/nested_cv.py 的特征列表；基本无需改模型代码
4

标定 PBPK/PD 模型

这是移植中工作量最大的一步：给药途径变了（关节腔→肌肉/皮下），房室结构就要重画；PD 指标变了（镇痛→血药浓度/受体占有率），效应模型也要换。实操建议：先拿一个体内数据完整的标杆产品（如本论文的 Zilretta®）做标定，让模型复现其体内行为，再谈预测新产品。

输入
标杆产品的体内 PK/PD 数据（文献或自有）
输出
标定后的房室模型 + 反推出的目标释放曲线
换产品要改
models/pbpk/ 下的房室结构、转运速率、PD 方程与阈值
5

跑两轮闭环优化

第一轮：在宽松处方空间做贝叶斯优化，预期会失败——失败是设计的一部分，它告诉你空间的哪些区域不可行。分析失败处方的共性（突释太高？速率太慢？），收缩搜索空间后跑第二轮。本轮的 F4 就是你的头号候选处方。

输入
ML 模型 + 目标窗口 + 搜索空间定义
输出
候选处方（组成 + 预测释放曲线 + f₂ 评分）
换产品要改
bayesian_opt.py 的 SEARCH_SPACE 与 MockMLPredictor（应替换为步骤 3 的真实模型）
6

MD 模拟做分子层面复核

对候选处方做 API-辅料 MD 模拟，确认相互作用强度符合缓释预期。若结合松散（氢键少、距离远、扩散快），说明处方可能突释偏高，回到步骤 5 调整 API 浓度或 PLGA 规格。

输入
候选处方的分子结构（API SMILES + 聚合物模型）
输出
氢键/接触/距离/扩散四项指标
换产品要改
md_summary.py 仅为示意；正式应用需 GROMACS/AMBER，此步通常需计算化学支持
7

湿实验验证，数据回流

只把计算胜出的 1-3 个候选处方送进实验室做体外释放。实测曲线与预测对比：偏差本身就是新数据——把它加入数据集（步骤 2），下一轮模型会更准。这就是"闭环"的真正含义：计算与实验互为输入，越转越聪明。

输入
候选处方（通常 1-3 个，而非传统的几十个）
输出
实测释放曲线 → 回流数据集
成功标志
实测 f₂ ≥ 50，且关键属性全在窗口内

FAQ移植时的三个关键决策

Q1：我的数据只有几十个处方，够吗？
本复现证明 155 处方足够训练 R²≈0.9 的树模型。少于 50 个时建议：① 并入结构相近的文献数据扩大样本；② 用更简单的模型（RF 而非深度模型）；③ 重点依赖 PBPK/PD 机制模型，ML 只做辅助修正。
Q2：换给药途径（如皮下而非关节腔），哪些模块能直接复用？
数据集构建流程、ML 训练流程、f₂ 相似因子、贝叶斯优化策略全部可直接复用——它们是途径无关的。必须重做的是 PBPK 房室结构和 PD 效应模型（步骤 4）。
Q3：没有 MD 模拟条件，能跳过步骤 6 吗？
可以，MD 是"锦上添花"的验证层而非必需环节。替代方案：用 API 理化描述符（logP、pKa、氢键供受体数——数据集里已有）做经验判断，或直接依靠步骤 7 的湿实验把关。
一句话总结：这套框架把 LAI 处方开发从"大批量试错"变成"目标驱动的计算筛选"——定义目标 → 数据建模 → 虚拟筛选 → 精准验证。任何长效制剂产品都可以套用这个七步流程，需要替换的只是数据和生理模型参数，方法论骨架完全通用。
